## What the staged flow did (compared with run 4)

- **It followed the stages.** Layers got a `source` (fetch 8, generate 1, construct 11, stock 1, skip 4), fetch layers got a real file, skipped layers carry a reason, the design file was written with `"brief"` and built in parts, then five full builds, then export and the report. - **No placeholder claw, no overlap flags, no wing claws dropped by the guard** (the same-panel guard of quick win 6 and the fetch gate did their job). The stock-based textures were built at the declared sizes (512x512 and 1536x1536).
- **The staged flow itself held up with a model**: 62 tool uses, no dead end in `apply`, `--only` or the round counter.
- **The score did not move (35 = run 4).** What it gained in process it gave back in the art: the claw is real but small, the roof claw and the door card detail are missing, the tonal art is thinner than in the references. These are the same open items as before (art sources, sizes), not new faults.

## Stumbles (kit changes to make)

1. **`brief show` prints only the file name of a reference**, so the model had to open `brief.json` to learn where the photos are. Print the full path (or the folder once).
2. **A batch run cannot reach DONE.** `brief show` kept asking the user to confirm 5 brand reads (Porsche crest, the wing lettering and others at medium confidence). The prompt says to record the default in `decisions`, but nothing in the brief accepts that as an answer, so the brief ends "NEXT (ask the user)" although the work and the report are done. Needed: a way to record "assumed by default, user not asked" per layer that clears the gate and shows up in the DONE summary as an unconfirmed read.
3. **A false `missing:` line for T. THIELE.** The layer says "roof edge strip"; the model placed it on the roof-edge panels (`left_mid_upper_2`, `right_mid_upper`), but those panels sit in the car's side regions, so the check wanted something in a "roof" region. The model explained it in a decision. Make "roof edge/strip" a place that the side or upper-side regions answer, or let `covers` clear it.
4. **Two elements were still flagged "cut off"** in the last build (`build.cutOff: 2` in the brief); which ones was not looked at. The check uses a simplified outline, so some may be false alarms (pixel masks, open item O7).
5. **The `ac-verify` / `ac-read-photo` skills were not visibly used** (no per-element crops, no view checks in what it left). Whether the skills are too long, not linked at the right moment, or simply optional is unknown until its transcript is read. Next run: ask the model to log which skills it opened (it can: the prompt allows reading them).
6. Still open from before: real art for the leaves and SC discs (O2, O4), the top view and roof claw, the door card detail, B12 view labels.
